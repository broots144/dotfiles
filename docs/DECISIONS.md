# Decisions

Append only. A later decision supersedes an earlier one; earlier entries are never rewritten.
Homelab-wide decisions live in the sublevel repo as ADRs and are cited as `sublevel ADR-NNN`.

- D-001 (2026-06-09): The Brewfile is the record of installed Homebrew and Mac App Store software. The interactive `brew` wrapper records installs; `brew-reconcile` on a LaunchAgent catches everything installed out of band. Both commit `brew: ...` straight to `master`.
- D-002 (2026-09-26): Unattended publishing pushes only when its own Brewfile commit is the single unpushed commit, and commits only the Brewfile. Pinned by test/brew-sync-push.sh.
- D-003 (2026-09-27): The off-site copy of ~/dev is a nightly copy into iCloud Drive; secret-shaped and gitignored files and git history go only into age-encrypted archives. Private keys (~/.ssh, ~/.config/sops) are never copied there.
- D-004 (2026-09-28): Repo data is data: prompt and git helpers never execute repo-local git config. Pinned by test/untrusted-input.sh.
- D-005 (2026-10-14): GitHub is the hub for ~/dev on both Macs (sublevel ADR-069, ADR-071). dev-pull only fast-forwards; it never resets. Private files move by rsync with `--update`, from n0 to the laptop on a schedule and back only by hand (`dev-push-to-n0`).
- D-006 (2026-10-28): LaunchAgents are host-gated by a `dotfiles-hosts` marker in the plist, matched against `HostName`.
- D-007 (2026-10-30): The MacBook upgrades Homebrew nightly at 23:45 (sublevel ADR-088); macOS itself stays manual.
- D-008 (2026-11-06): Repo-state pattern adopted. STATE.md is the single source of current truth. A CI guard on pull requests fails when code changes without a STATE.md change, except PRs whose commits are all `chore:`, `deps:` or `brew:`. Direct `brew:` pushes to `master` are not gated.
- D-009 (2026-11-07): dev-pull treats every checkout as untrusted (D-004 extended to the unattended fetch/merge): it fetches only GitHub origins plus a local trusted-origins list, skips repos whose local config could name a command, runs with hooks off and only the https/ssh transports, and pushes WIP snapshots only to private repos, scanned with the dotfiles' own gitleaks config.
- D-010 (2026-11-07): herdr 0.9.5 is the agent multiplexer on n0, from Homebrew (latest release, so no install script), held with `brew pin herdr` and recorded in `herdr/VERSION`; `[update] version_check` and `manifest_check` are off so the binary and its agent-detection rules change only when the pin moves (docs/herdr.md, Upgrading). The Claude Code integration (`herdr integration install claude`, integration version 11) was read at the v0.9.5 tag before it ran (`src/integration/claude_settings.rs`, `src/integration/assets/claude/herdr-agent-state.sh`) and diffed after: it wrote one file, `~/.claude/hooks/herdr-agent-state.sh` (0755, byte-identical to the tag's asset), and added exactly one entry to `~/.claude/settings.json`: `hooks.SessionStart` matcher `^(startup|resume|clear|compact|fork)$`, command `bash '<home>/.claude/hooks/herdr-agent-state.sh' session`, timeout 10. Nothing else in settings changed (the existing claudebar hooks are untouched). The hook exits at once outside a herdr pane (`HERDR_ENV`, `HERDR_SOCKET_PATH`, `HERDR_PANE_ID`), reads the hook JSON and, on SessionStart only, sends `pane.report_agent_session` (session id, transcript path) to the pane's herdr socket; it never reads or reports prompts or output. Working, blocked and idle come from herdr's screen detection, verified live with two Claude sessions (a Write permission prompt and the folder-trust prompt both read `blocked`). Reinstalling the integration rewrites both; re-read the diff on every pin move. `pane_history = false` keeps screen history off disk.
- D-011 (2026-11-07): The default herdr server runs as the n0 LaunchAgent `com.broots.herdr-server` (`bin/herdr-server`), KeepAlive on a crash only, with a fixed PATH, SHELL and LANG, so panes never inherit the environment of whichever terminal or SSH session happened to start the server first, and the socket exists after a reboot for the Atlas agent view. `~/.config/herdr` is set to 0700 by the wrapper and by `herdr/install.sh`: herdr makes its API and client sockets 0600 (owner only; `src/server/socket_paths.rs:12`, chmod after bind at `src/api/server.rs:91`) but leaves the directory 0755 and session.json and its logs 0644, and n0 has another local account (gha-runner) running CI jobs. The sockets are a full control API (send text and keys, run commands in panes) with no peer credential check, so the file modes are the whole access control; nothing may loosen them. The config is a symlink to the tracked `herdr/config.toml`; herdr writes UI changes through it (`std::fs::write`, `src/config/write.rs:67`), which shows them as a git diff to commit or revert.
- D-012 (2026-11-08): herdr's agent-detection rules come only from the pinned binary ("bundled"). `manifest_check = false` stops this config's servers from fetching rules from herdr.dev, but the remote cache (`~/.local/state/herdr/agent-detection/remote`) is shared by every session and any herdr started without this config (here: a Phase 0 test session) refills it, and then every server loads those rules. `bin/herdr-server` removes that cache before the server starts, and `verify-phase-8` fails unless `herdr server agent-manifests` lists every rule as `bundled` with no remote check (security audit dotfiles run-5 lead).
- D-013 (2026-11-08): Security audits of this repo execute target code only inside `~/security-audit-skill/_sandbox/sandbox-run` (outside every repo): a Seatbelt `deny default` profile (no inet socket at all, loopback included; unix sockets only inside the agent's scratch; reads limited to the system, Homebrew, the read-only target worktree, named toolchains and scratch, never the rest of $HOME; writes to scratch only), an empty environment rebuilt from an allowlist with scratch-local HOME, TMPDIR and caches, kernel rlimits for CPU, file size, open files, processes and core dumps, and a watchdog that kills the process group over the memory or wall-clock bound (macOS does not enforce RLIMIT_AS). `selftest.sh` proves all 17 controls before a run (blocked TCP, UDP, loopback bind, DNS and curl; home and other repos unreadable; host sockets such as herdr's unreachable; target read-only; env allowlist; memory, CPU, wall clock and file-size kills). Scratch files reach a run's artifacts only through `promote.py` (no-follow descriptor walk, regular single-link files, size bounds, exclusive creation). Audit output stays in `~/security-audit-skill/dotfiles/run-N`, never in git.
